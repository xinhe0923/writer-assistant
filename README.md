# 断点续写 · 小说写作套件

AI 只负责记忆、提问、查设定、写摘要；**正文只由我写**。规则见 [CLAUDE.md](CLAUDE.md)，方案和已定决策见 [docs/HANDOFF.md](docs/HANDOFF.md)。

## clone 之后先做一次

```bash
git clone <仓库地址>
cd <仓库目录>
git config core.quotepath false   # 否则中文路径在 git 输出里会变成八进制转义，字数脚本会出错
```

然后用 Obsidian（或任意编辑器）打开这个文件夹写正文，在 Claude Code 里用这个文件夹开一个会话跑命令。

## 日常流程

1. **开工**：`/go` → 看前情、停在哪、下一句开头、这次的小任务（10–15 分钟）。第一次在空仓库上运行会先问 4 个问题，生成 大纲.md、断点.md 和空的 正文/001.md。
2. **写**：在编辑器里写 `正文/` 下的章节文件（001.md、002.md…）。想先跳过的地方自己打上 `【待定：一句话】`。
3. **卡住**：`/stuck [卡在哪]` → 先回答 3 个问题，再拿到 5 个一句话的方向。
4. **查设定**：`/lore <问题>` → 带 `文件:行号` 的回答。
5. **收工**：`/done [下一句开头]` → 统计字数、更新摘要和设定、重写断点，分「正文」和「记忆」两次提交并 push。

## 命令表

| 命令 | 用途 | 参数 | 模型 |
|---|---|---|---|
| `/go` | 开工：读断点，≤250 字告诉你从哪接着写；空仓库时冷启动 | 无 | Sonnet |
| `/stuck` | 卡住了：3 个问题 → 5 个方向（顺/逆/狠/暖/怪） | 卡在哪（可选） | Opus |
| `/done` | 收工：字数、摘要、设定、断点、两次提交、push | 下一句开头（可选） | Sonnet |
| `/lore` | 查设定：≤100 字，每条注明 `文件:行号` | 问题 | Sonnet |

命令文件在 `.claude/skills/<命令>/SKILL.md`。每个命令的 `model` 只对调用它的那一轮生效，下一条消息回到会话本身的模型。所以：

- `/stuck` 问完 3 个问题后，如果想让第二轮也用 Opus，用 `/stuck <你的回答>` 回答；直接回复的话，第二轮用的是会话当前的模型。
- 建议把本地写作会话的默认模型设成 Sonnet（`/model sonnet`）。

## 字数口径

`tools/wordcount.py` 统计 `正文/*.md`（只算 正文/ 下一层的 .md 文件）：

- 算：所有非空白字符，**标点算字**。
- 不算：空格、换行等空白；Markdown 标记（标题的 `#`、强调的 `*` `_`、链接语法 `[文字](地址)` 只算「文字」，Obsidian 的 `[[链接]]` 同理）；HTML 注释 `<!-- -->`；`【待定：…】` 占位。
- 比较工作区和上一次提交（HEAD）：新文件全算，删除的文件算负数，还没有提交时全算。

想改口径（比如不算标点，按目标平台的算法），改 `tools/wordcount.py` 里的 `count_chars`，再跑一遍测试。

```bash
python3 tools/wordcount.py          # 看本次各文件新增字数和累计字数
python3 tools/wordcount.py --log    # 同上，并写进 日志.csv（/done 用）
python3 -m unittest                 # 跑测试
```

## 提交约定

- 正文提交：只含 `正文/`，信息为「正文：<文件> +<N>字」，不加 Co-Authored-By。
- 记忆提交：其余改动，信息为「记忆：<简述>」，结尾加 Co-Authored-By 行。

想让正文提交也加 Co-Authored-By，改 CLAUDE.md 的「提交」一节。
